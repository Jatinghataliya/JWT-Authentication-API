Admin Panel — System Design

Architecture, tech choice, screen breakdown, API mapping, auth flow, and implementation plan — grounded in the existing JWT Auth API (20 features, Spring Boot 3.2, PostgreSQL).

1. Technology Choice

✓ RECOMMENDED
React + Vite (SPA)
Single-page app, calls existing REST API directly. JWT stored in memory. Fastest UI, full control. No backend changes needed.
ALTERNATIVE
Spring MVC + Thymeleaf
Server-rendered HTML inside the same Spring Boot app. No CORS. Simpler deploy. But slower UI and tightly coupled.
AVOID
Next.js / full-stack
Overkill for a standalone admin panel. Adds SSR complexity with no benefit when the backend already has all the data.
Why React SPA? Every endpoint the admin panel needs already exists — GET /api/admin/users/paged, GET /api/admin/audit/paged, role CRUD, account actions. The panel is purely a consumer of the existing API. No backend code needs to change.

Dev: Vite proxy forwards /api/* to :8080 — no CORS config needed. Prod: Nginx serves the React build at / and proxies /api/* to Spring Boot.

Token storage security decision: Store the access token in JS memory (React state / Zustand). Never in localStorage (XSS-readable). Use an HttpOnly cookie for the refresh token so JS cannot read it but the browser sends it automatically on token refresh calls.

5. Authentication Flow in the UI

1
Login — Admin submits username + password → POST /api/auth/login.
Response contains accessToken (JWT, 15 min) and refreshToken (UUID, 7 days). Check roles array — if it does not contain "ADMIN", show "Not authorised" and discard the token.
2
Store tokens — accessToken in React/Zustand memory state only. refreshToken in an HttpOnly cookie (set by the browser on Set-Cookie, or stored in memory if the API doesn't use cookies yet).
Memory storage means the token is lost on page reload — that's correct and secure. The refresh token handles silent re-login.
3
Attach to every request — Axios interceptor adds Authorization: Bearer <accessToken> to all /api/admin/** calls automatically.
One interceptor, zero per-component boilerplate.
4
Silent refresh — A second Axios response interceptor catches 401 errors. On 401, it calls POST /api/auth/refresh with the refresh token, stores the new access token, and retries the original request transparently.
If refresh also returns 401 (expired), redirect to /login.
5
Logout — Call POST /api/auth/logout (blacklists the JTI), clear memory state, redirect to /login.
The logout API call ensures the server-side blacklist entry is created even if the user closes the tab — if they don't close the tab.

8. One Backend Change Needed — CORS

The only Spring Boot change required is enabling CORS for the React dev server origin. Add this to SecurityConfig.securityFilterChain():

.cors(cors -> cors.configurationSource(request -> {
CorsConfiguration cfg = new CorsConfiguration();
cfg.setAllowedOrigins(List.of("http://localhost:5173")); // Vite dev server
cfg.setAllowedMethods(List.of("GET","POST","PUT","PATCH","DELETE","OPTIONS"));
cfg.setAllowedHeaders(List.of("*"));
cfg.setAllowCredentials(true); // needed for HttpOnly cookie refresh token
return cfg;
}))
Production CORS: Replace localhost:5173 with the actual deployed origin (e.g. https://admin.yourdomain.com). Never use * with allowCredentials(true).
